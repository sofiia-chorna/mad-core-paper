
# Stage C: direct fit of the full 2^20 at d=8 on 64 GPUs

**Goal:** `fit` the real objective on all 1,048,576 coreset points. Not `transform`, not
landmarks + out-of-sample. This is the deliverable (`handoff.md` calls it "optional stage C:
global refinement of the full weighted 2^20 stress on GPU").

No landmark stage, no projection stage. Straight to the full fit.

## The whole recipe

```python
from sklearn.decomposition import PCA

X = <first 2**20 rows of center_feats_scaled.f32>        # (1048576, 512)
init = PCA(n_components=8).fit_transform(X)              # seconds — see below
w = np.load("populations_level20.npy").astype(np.float64) ** 0.25
w = w / w.sum()                                          # N_eff = 698,224 / 1,048,576

fit(X, w, init=init, n_components=8,
    sigma=1.24, a_high=4.0, b_high=2.0, a_low=2.0, b_low=2.0,
    center=False)
```

## Why init=PCA, and why it is not a compromise

`fit` falls back to `classical_mds` when `init is None` (`_sketchmap.py:719-731`), and
`classical_mds` (`_sketchmap_utils.py:143`) does `gram_matrix = distances**2` on the full
**N x N** matrix, then eigendecomposes it. At N=2^20 that is **8.8 TB** and O(N^3) = 1.2e18
FLOPs. It cannot run — and it is the `else` branch, so it fires automatically unless `init`
is passed.

**For Euclidean distances, classical MDS and PCA are the same embedding.** Verified on our
data (n=3000, d=8): pairwise-distance correlation between `classical_mds(cdist(X,X), 8)` and
`PCA(8).fit_transform(X)` is **1.0000000000**, identical up to rotation. classical_mds
recovers it from an N x N eigendecomposition because distances are all it is given; PCA gets
the identical answer from the **512 x 512** covariance because it has the coordinates.

|                   | matrix    | FLOPs at 2^20 | memory |
| ----------------- | --------- | ------------- | ------ |
| `classical_mds` | N x N     | 1.2e18        | 8.8 TB |
| PCA               | 512 x 512 | 2.7e11        | 2.1 GB |

So `init=PCA` loses nothing. Passing `init` also skips the MDS refinement (line 735).

## Parameters — re-derive sigma, do NOT carry 2.00 over

| --------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| wgamma=0.25     |                | **N_eff = 698,224 of 1,048,576 (67%)** — far healthier than the landmarks' 3,853/16,384, because a million cells spread the density. Still Michele's open call.                                                                                                                 |
| center=False    |                | no-op mathematically (stress differs 5e-09); keeps`_X_processed_` bit-identical to `center_feats_scaled.f32`                                                                                                                                                                       |

**sigma must come from the pair-weighted histogram** — the stress is
`sum_ij w_i w_j (F-f)^2`, so the weighted distribution is what the sigmoid must sit on.
`suggest_sigmoid_params` cannot help here: it takes bare `distances` and never sees the
weights.

## Torch implementation

- **Never materialise the pair matrix** — 8.8 TB. Tile it: each GPU owns a row-block of Y,
  all-gather Y each iteration (N x 8 = **34 MB**, trivial), compute the block's d, f and
  gradient contribution, reduce-scatter the gradients.
- **Recompute F(D) per eval rather than caching it.** Caching costs 2.2 TB fp32 = 34 GB/GPU
  across 64; recomputing is N^2 x 512 x 2 = 1.1e15 FLOPs = **~0.17 s/eval** on 64 GPUs.
  10x slower per eval and still ~3 min for 1000 iterations — take the simpler code and skip
  the multi-TB allocation. (Cache in fp16 = 17 GB/GPU only if the eval count makes it pay.)
- Low-D side per eval: `Y @ Y.T` = 1.8e13 FLOPs -> ~0.003 s. The fit is **memory-bound, not
  compute-bound**.
- fp32 for the low-D side and the accumulation.

**Validate the port against `experiments/09_skmatter_compare/` before running at 2^20** —
1024 points, with both a C++ reference and a passing numpy reference (stress ratio 1.001,
map correlation 0.9915). A torch port that reproduces those has an exact target. Do not
debug at 2^20.

## What to expect — and the number to watch

**PCA already scores 1.67x family locality at d=8**, versus sketch-map's 1.75x at 2^14. Since
the init *is* PCA, the fit starts close to a decent answer. **If Stage C lands at ~1.67x it
has not moved off its init** — that is the diagnostic, not the stress value.

Also, honestly: the 2^20's distances are **more** concentrated than the landmarks'
(5-95% spans 2.8x vs 3.5x), so the sigmoid filters *less* — **96.6%** of pair-weight lands
mid-sigmoid at sigma=1.24, vs 73.9% for the best landmark run (W2). The direct fit may come
out **more** PCA-like, not less. It is still the right thing to do (it optimises the true
objective rather than a landmark approximation), but do not expect the picture to improve on
that account. Report `vsPCA` alongside family locality.
