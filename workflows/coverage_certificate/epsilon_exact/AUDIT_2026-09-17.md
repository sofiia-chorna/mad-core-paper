# Audit of `epsilon_sq`, the separation-coverage guarantee, and the k-set inset

Date: 2026-09-17. Scope: `release/mad-core` (2^24 rows), appendix Table `tab:accrete-levels`,
Figure `fig:coreset224-kset` inset. Nothing in the store or the manuscript was modified.

Every statement below is tagged **[established]** (follows mathematically from definitions and
the code path), **[verified]** (numerically checked today or by a surviving artifact, with
precision stated), or **[unverified]** (no surviving artifact; only a transcribed number or a
self-consistency argument).

## 0. Retraction

The 2026-09-17 chat message that said the appendix table was "verified twice" and that
cov(S_k) "equals the largest exact separation inside level k+1" was wrong in direction.
The largest insertion distance inside level k+1 sits at the first FPS fill pick, which is
taken **after** the level's anchor admissions. That value is cov over the pool of
S_k ∪ {admitted anchors}, which is ≤ cov_X(S_k). So what was reproduced today is a
**lower bound** on the table's coverage, to three decimals. The guarantee
sep(S_k) ≥ cov_X(S_k) needs an **upper** bound on coverage. Separation was independently
verified; coverage was not.

## 1. Event order inside an accretion level (code, production commit lineage)

Driver: `accrete/run_accrete.py` → `coresets.cuda.multi.sharded.accrete_sharded` →
`coresets/src/coresets/cuda/multi/_base.py`. The repo HEAD (67a932d) is two commits after
the production commit 4285ea0; the only change is the `CORESETS_ANCHOR_COV_RELAX` knob,
default 1.0, not exported in `runs/madcore_production/submit_accrete.sh`. The 4285ea0 tree
itself is unreadable in the scratch clone (purged objects), so "same logic" rests on
`git log 4285ea0..HEAD` showing only that knob.

Per level k (`_do_layer`, `_base.py:359-405`):

1. Budget = 2^k − |selected| (level 20 partial: target 856,012).
2. Anchor admission (`_do_block`, `_base.py:408-539`): for each nested anchor block
   A_k ⊂ A_{k+1} ⊂ … (first 2^i points of the MAD-union FPS order, `_base.py:144-146`),
   greedy **restricted FPS** over the block's not-yet-selected members
   (`_restricted_argmax`, farthest-first within the block), then a bisection for the
   largest prefix m whose completion by simulated global FPS still passes sep > cov at
   level end (`_bisect`/`classify`/`viable`, `_base.py:579-757`), rollback, replay m picks.
3. Global FPS fill of the remaining budget over A ∪ C (`_fill_many`, `_base.py:554-564`).
4. Level-end check `check_invariant_global` (`_shared.py:405-455`):
   `cov_sq = all_reduce_MAX(hausdorff_shard.max())` over **all 184,180,658 rows**,
   `sep_sq` = running minimum of insertion distances; abort if
   `sep_sq < cov_sq·(1 − 1e-3)`. float32. This is what the table prints (`print_level_row`).
5. Checkpoint: selected ids + `sep` only. **cov is never persisted.**

Consequences:

- **[established]** sep(S) = min over picks i ≥ 2 of r_i (distance of pick i to its nearest
  earlier pick), for any admission order. The stored stair equals sep(S_k).
- **[established]** max_{i in level k+1} r_i ≤ cov_X(S_k). Equality is not implied.
- **[verified]** In every level 2..20 the argmax of r_i is exactly the first global-fill
  pick (position = number of anchors admitted in that level; see table in §4). So the
  reproduced number is cov_X(S_k ∪ admitted anchors).
- **[established]** Inside a level, after admissions and before the fill completes, no check
  runs. The guarantee is asserted for **completed levels only** through 856,012.
- **[established]** From 856,012 on, plain FPS: for every prefix n, the insertion distance of
  pick n+1 equals cov_X(S_n) and sep(S_n) = min(sep(S_856012), r_856013..r_n) ≥ r_{n+1},
  given sep(S_856012) ≥ cov_X(S_856012) from the last accrete check. Holds for **every
  prefix** n ≥ 856,012, in the arithmetic in which the picks were made (float32).

### Tolerances and what "established" can mean per level

Run-time test: sep² ≥ (1 − 1e-3)·cov², float32. Table margins sep²/cov² − 1:
8.6e-2, 5.7e-1, 5.0e-2, 1.4e-2, 1.5e-2, 2.0e-3, 8.6e-4, 1.8e-3, 4.8e-4, 2.8e-4, 3.2e-4,
6.5e-5, 8.5e-6, 3.0e-5, 1.6e-5, 2.7e-6, 5.7e-6, 2.8e-6, 9.4e-7, anchor 1.5e-6.

- k ≤ 11: margin ≥ 2.8e-4, above float32 distance noise (~1e-4 relative on squares at these
  magnitudes). The run-time check establishes sep ≥ cov over X up to that noise. A float32
  `voronoi_d` pass over a pool mask can certify these independently.
- k = 12: margin 6.5e-5, borderline for float32.
- k ≥ 13 and the anchor: margins 1e-6..1e-5 are **below float32 resolution**. sep and cov
  are numerically indistinguishable there; a float64 recomputation can land on either side.
  Only a float64 coverage pass over X can settle them, and the manuscript's own sentence
  ("reported values rather than certified ones") should stay until then.
